# TwilightRain 的文本工具

处理中文稿件的桌面工具，附带一套命令行。四个处理功能：把被硬换行截断的句子接回去、把几份稿子接成一份、把标点换成另一种、把剧本排成一句一行；另有文字检查，只指出读起来像机器写的措辞，不改字、不动文件。

图形界面与命令行共用同一套引擎，同一份输入、同一组参数，两边产物逐字节相同。

## 程序特点

- 原生程序，Windows 与 Linux 的程序都把运行库静态链进去了。
- 界面自带一份中文字体，换一台没配过字体的机器，字形也是同一副样子。
- 界面默认 1000x620，最小 900x560；屏幕更大时按比例放大。
- 界面只有简体中文；程序不含自动更新、多语言与繁简转换功能。

## 界面

页签三项：处理、关于、高级。高级下拉里是五个参数页。

### 处理

平时只盯这一页：

1. 选一份稿子，或者选一个文件夹。
2. 在清单里勾要做的几件事：接回断裂的句子、合并多份稿子、换稿子的标点、检查是不是机器写的；「更多功能」里还能加「排版视觉小说」。
3. 按「开始处理」。

处理结果写在源文件旁边，名字是原名加 `_Processed`，按原稿的编码写回。

- 「先看效果」在右侧展开预览面板，只显示结果开头两万字；面板里的「保存」会按同一组设置重跑一遍，把完整结果存到你挑的位置。
- 「直接改原文件」会写回原稿；不勾「改之前先留一份备份」时，动手前会再问一次。
- 勾了「检查是不是机器写的」，处理完可以打开「报告面板」按文件看人读报告。报告与命令行 `texttool lint` 打出来的那份排版相同。
- 合并多份与接回、换标点、排版不能一起跑；检查与任何组合都能共存，永远最后跑。

### 高级

| 页 | 管什么 |
| --- | --- |
| 接回断行 | 分段按字节还是按字数、多长断开，以及四项附加处理 |
| 合并多份 | 合并出来的文件叫什么 |
| 换标点 | 这次的替换规则列表、从预设方案里挑、新建与编辑方案、存回规则文件 |
| 剧本排版 | 补标点与排段落怎么组合、每段最多几个字、用哪几份角色表 |
| 文字体检 | 显示哪些问题、稿件类型、只查指定的几条、改一条检查项；另有「记下检查命中」勾选框，默认关闭 |

### 关于

版本、作者、仓库地址、备份设置与恢复设置、深浅色切换。标题栏会跟着底色一起变。

## 命令行

```text
texttool merge <文件...> [选项]       行合并加后处理
texttool replace <文件...> [选项]     标点替换
texttool vn <文件...> [选项]          视觉小说排版
texttool join <目录> [选项]           文件拼接
texttool lint <文件|目录...> [选项]   文字检查，只报不改
texttool calibrate [选项]             规则标定：人类文本与模型文本两侧对比
texttool reply-check [选项] [文件]    回复里读者解不开的写法，只报不改
```

每个命令都有自己的 `--help`。几条通用的：

- 输入可以给多个文件、一个目录，或者 `-` 从标准输入读。目录递归收 `.txt` 与 `.md`。
- 退出码 0 是正常，1 是有问题或检查有命中，2 是用法或读取错误。
- `lint --json` 的输出顶层是 `Version: 4`，命中带编号、行号、列号与原文片段。
- 处理类命令支持 `--overwrite`、`--backup`，与界面上的「直接改原文件」「先留一份备份」做的是同一件事。

## 配置放在哪

配置文件与程序在同一个目录，整个目录可以直接拷到别的电脑。界面与命令行各读自己所在目录的那一份；把两个程序放在同一目录，改过的规则两边立刻共用。

| 文件 | 内容 |
| --- | --- |
| `replace_rules.json` | 换标点的规则列表 |
| `replace_schemes.json` | 有名字的替换方案 |
| `vn_schemes.json` | 角色表与路线名 |
| `lint_rules.json` | 改过的检查项，按编号覆盖内置那条；没有就是全用内置 |
| `default_lint_rules.json` | 内置检查表，随包发 |
| `default_vn_schemes.json` | 内置角色表，随包发 |

界面自己的偏好（上次浏览的目录、深浅色、要不要记检查命中）不在程序目录，放在用户配置目录：Linux 是 `~/.config/texttool/ui.conf`，Windows 是 `%APPDATA%\texttool\ui.conf`。

「记下检查命中」默认关闭。打开以后，每次在「处理」页勾「检查是不是机器写的」并跑完，会把全部命中按命令行 `--log` 的格式追加写到用户状态目录：Linux 是 `~/.local/state/texttool/hits.jsonl`，Windows 是 `%LOCALAPPDATA%\texttool\hits.jsonl`。打开它会明显多占内存，排查完记得关掉。

## 从 3.x 搬配置

4.0 只认上面那张表里的文件，`app_config.json`、`last_known_version.txt` 这类文件名不读。

自定义的规则、方案、角色表要搬过来：在 3.x 里用「导出配置」存一份包，在 4.0 的「关于」页按「恢复设置」导入。导入前会先整份读通，读不通就一个字不写。

## 安装包

| 平台 | 界面 | 命令行 |
| --- | --- | --- |
| Windows x64 | `texttool-windows-gui.zip` | `texttool-windows-cli.zip` |
| Linux x64（麒麟） | `texttool-kylin-gui.zip` | `texttool-kylin-cli.zip` |

解压到任意目录，直接运行，不用安装。每个包旁边有 `.sha256` 与 `.sig`：`.sha256` 给下载的人核对文件有没有传坏；`.sig` 是发布签名。程序不含自动更新，也不自己验签。

Linux 版需要系统里有 X11 与中文字体的基础库（多数桌面发行版自带）；界面文字用的是随包字体，不依赖系统装了哪款中文字体。
