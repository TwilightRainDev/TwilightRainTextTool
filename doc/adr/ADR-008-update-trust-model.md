# ADR-008: 自更新信任模型——离线签名 + 公共根 TLS 固定

## 状态
已接受（2026-08-03）；**决策 2 已修订（2026-08-03）**——公共根 TLS 固定由默认开启改为默认关闭（opt-in），详见"修订说明"

## 背景
安全审计（security-audit 流程）发现自更新模块的信任链单点失效：

- zip 与其 `.sha256` 从同一 HTTPS 端点、同一 TLS 会话下载——hash 是自引用校验，对中间人（能 MITM TLS 的代理/私有根 CA）与仓库被攻破**均无防护**，只能防意外损坏
- 无代码签名验证、无证书固定。实测本机运行 Steamcommunity302 类加速器时，`api.github.com`/`objects.githubusercontent.com` 的 TLS 证书被其本地代理 + 自签 CA 完全接管（CA 已装入系统根存储，OS 级校验通过）——攻击者若控制该代理即可对 `texttool update` 投放任意代码
- 个人开发者无付费代码签名证书，Authenticode 路径不可用

## 决策
重建更新信任链，信任根从"GitHub 网站"移到"开发机私钥"：

1. **签名验证（信任根）**：ECDsa P-256，私钥仅存开发机（`E:\work_zone\ApiKey`）离线签名，产出 `<zip>.sig`；公钥 SPKI 内嵌客户端（`ReleaseSigningPublicKey.cs`）。客户端下载 zip + `.sig` 验签，**缺失/无效一律中止，无 sha256-only 降级路径**。`.sha256` 保留，仅作传输完整性检查。
2. **TLS 公共根固定（默认关闭）**：`pinned_roots.txt`（嵌入式资源，由 certifi/Mozilla 公共根清单生成，121 个 SPKI）——仅 `TEXTTOOL_UPDATE_STRICT_TLS=1` 时启用，链根公钥不在白名单即拒绝。默认模式为 OS 信任 + 检测告警（链根非公共 CA 时 CLI 提示，不中断）。**不**做叶证书/精确根固定：GitHub 会轮换 CA，且本机 TLS 被劫持无法取证真实链。

### 修订说明（决策 2）

签名（决策 1）落地后，中间人已无法伪造更新内容（`.sig` 验签兜底），TLS 固定的安全边际只剩"静默假更新 → 响亮报错"的检测价值；而国内 DNS 污染环境下，S302 类 hosts 劫持加速器是主流连法，强制固定会让这部分用户**完全无法更新**——可用性代价超过边际安全收益。因此默认放开，固定降级为 opt-in 加固项。残余暴露：恶意的 MITM 代理可伪造"无更新"响应（与直接断网等效），无法伪造更新本身。
3. **下载主机白名单**：`UpdateClient` 禁自动重定向，逐跳校验 https + `github.com`/`objects.githubusercontent.com` 等白名单主机。
4. **严格版本白名单**：`^v?\d+\.\d+(\.\d+)?$` + 分量 ≤9999，非法版本显式报错（堵住"溢出 tag 永久瘫痪更新通道"）。
5. **本地加固**：随机临时目录、落盘后重读复验 hash、解压总量/条目上限、批处理脚本 `%` 转义、robocopy 失败保留 staging 并报错。
6. **单次请求**：`tag_name` 与 assets 同一次 release 抓取，消除双重请求 TOCTOU。

## 后果

- **优点**：中间人（企业代理、Steamcommunity302/SteamTools 类、杀软注入）与仓库/账号被攻破均需获得私钥才能伪造更新——SHA256 同信道问题失效
- **优点**：零成本（无证书费用）；公钥轮换、锚点更新均为单文件改动
- **代价**：发布流程增加手动步骤（CI 构建 → 本地签名 → 上传 `.sig`）
- **注意**：运行 S302 类加速器的用户将收到明确的更新失败错误（TLS 锚点不匹配，预期行为）；公钥轮换需**两步发布**（先用旧私钥发一个内嵌新公钥的版本，再切换到新私钥）
- **注意**：签名密钥的安全性取决于开发机（私钥文件+系统登录），私钥绝不进入 GitHub/CI
