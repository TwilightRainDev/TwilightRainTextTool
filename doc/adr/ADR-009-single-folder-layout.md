# ADR-009: 程序本体与配置同目录（单目录哲学）

## 状态
已接受（2026-08-04）

## 背景
安全审计（2026-08）发现配置信任域问题：配置文件读写于程序安装目录（`AppContext.BaseDirectory`），且 `JsonFileStore.Load` 静默吞掉一切异常——配置损坏时规则无声消失，CLI 以错误配置运行。审计建议迁往 `%APPDATA%` 并显式报错。

但 TextTool 的既有形态与更新模型都以"程序目录即数据目录"为前提：

- 自更新（[[ADR-008-update-trust-model]]）通过 robocopy 整目录替换安装目录，前提就是该目录对当前用户可写——程序目录本就是可写目录，不存在"把配置放在只读程序目录"的风险
- 分发形态是绿色单目录（便携）：用户拷贝整个文件夹即完成迁移/备份/回滚
- 迁往 `%APPDATA%` 会分裂数据位置：程序在 D 盘、配置在 C 盘，便携性被破坏，回滚"旧程序文件夹"也回滚不了配置

## 决策
**程序本体与所有用户数据始终存放在同一个文件夹**（`AppContext.BaseDirectory`，即程序所在目录）。用户数据包括：

- 配置文件：`app_config.json`、`vn_schemes.json`、`replace_rules.json`、`replace_schemes.json`
- 状态记录：`last_known_version.txt`（自更新降级检测，见 ADR-008 修订）

由此得出三条推论：

1. **该目录必须对当前用户可写**——这是自更新与配置写入的共同前提，不接受"程序目录只读"的假设；
2. **配置损坏不得静默吞掉**——`JsonFileStore.Load` 区分"文件不存在 = 首次使用（fallback）"与"文件存在但解析失败 = 数据异常（显式抛 `InvalidDataException`）"；CLI 报错退出，GUI 弹窗提示。纯外观偏好（`app_config.json` 的语言/主题）允许静默回退默认值，因它不影响处理结果；
3. **配置写入一律原子替换**——临时文件 + `Move`（`AtomicFile`），崩溃不留下半写配置。

## 后果

- **优点**：单一数据位置，便携、易备份、易回滚（保留旧程序文件夹即保留旧配置）
- **优点**：自更新 robocopy 整目录替换天然携带最新配置
- **优点**：与既有实现零迁移成本，`%APPDATA%` 迁移方案作废
- **缺点**：同机其他用户/本地恶意软件可写该目录即能改配置（与 `%APPDATA%` 风险对等，本机单用户威胁模型不变）
- **缺点**：多用户共用一台机器时配置共享（当前单用户场景，不支撑）
