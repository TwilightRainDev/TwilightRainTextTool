# WorkZone

个人工作区。这里不是大厂，不用那么多规矩。我们有活力，规矩越少越好，目的就是把项目往前推。

# 这个工作区的几条规矩

## 1. 文件在会话中突然变了

先看看是不是伙伴自己在编辑器里保存了，再去排查是不是别的智能体在跑。

## 2. 密钥别明文放

把密钥塞进安装包、项目目录或远程仓库里，很容易泄漏。
让程序去读密钥，靠前缀和长度确认它是哪把密钥。

## 3. 临时文件要删

临时产物就放临时文件夹。只存一份还放在临时文件夹里不安全，随时可能被删。

## 4. 文档与注释

看的人是被分发、刚接手、时间紧迫的新开发者，他不希望看见文件名、编号、章节号、旧说法和引用。
正式写出来的内容，只放完整、能直接照着做的结果，一次说清楚。
写在哪里决定谁会看，谁会看决定写多长。

- 变更记录：怎么改的、以前什么样、为什么改、什么时候改，放到修改记录里。
整个工作区范围的改动放工作区更新记录，单个项目的改动放项目更新记录。

- 技术文档：文风按写注释的路子来，只写从代码和现状里看不出来的东西，以及怎么判断做得对不对。

- 注释：只写事实和现在该怎么做，要让他不用翻别的文件就能看懂、能照着做、能判断对不对。
改注释时顺手把前后改一致。

## 5. 接手已有项目

全信文档不可取，自己动手查。文档里每一条能被验证真假的说法，都拿本地文件和远程仓库重新对一遍。
发现对不上，先说，直接改会出事。
开始干活前别急着动手。先写你要做什么、做到什么算完成、要花什么代价。
万一双方想岔了，还能回到这几句话上对一对，确认说清楚了再继续。
