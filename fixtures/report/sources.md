# 报告渲染的对照样本

每个用例一份稿件，配人读报告、`--json` 输出、两次运行的退出码。

## 基准从哪来

`make_goldens.sh` 用两个构建出基准：人读报告用 4.0 的构建（用词以 4.0 为准），
`--json` 与退出码用 3.1 的构建（提交 `207dd38`，契约不动）。4.0 的构建由脚本开头那三行
从标签 `v4.0.0-draft` 导到临时目录再编，参考仓库不动。

同一批稿件在两个构建上的命中、全文长度、退出码逐字节相同，人读报告与 JSON 说的是同一批数据。
换了参考实现的提交，重跑脚本，不要手改 `.expected.*`：手改等于把基准改成自己的输出。

稿件名不带目录，报告里 `File` 字段就是它。运行中打到 stderr 的东西集中在 `make_goldens.stderr`，
非空就说明那一次运行有话说。

## 稿件来源

| 稿件 | 来源 |
| --- | --- |
| `real_doc_agents.md` | 工作区根目录 `AGENTS.md` 原样复制 |
| `real_doc_architecture.md` | 工作区 `Docs/Project/TextTool/ARCHITECTURE.md` 原样复制 |
| `collapse.txt` | 手写十一句对举句，处数过门槛、密度远超阈值 |
| `exotic_codepoints.txt` | 手写非字符、未分配码位、自用区、补充自用区、表情与隐形字符 |
| 其余 `.txt` | 为对照手写的短样本 |

两份真实文档只做复制；要更新就从原文件重新复制再跑脚本。

## 每个用例盯什么

| 用例 | 分支 |
| --- | --- |
| `no_hits` | 没有命中：`[通过]` 行、命中数为 0 的汇总行、`"Hits": []` |
| `mixed` | 两条命中分属两条规则 |
| `mixed_severity` | 警告级与提示级混排；同一规则两处按行列排序；带提示与方案 |
| `escaping` | `"` `\` `<` `>` `&` `'` `+` 与三个隐形字符 |
| `exotic_codepoints` | 非字符与未分配码位写大写十六进制，BMP 自用区写 `\uE000`，补充自用区写一对代理项，表情按码元成对；人读报告里这些字原样印出 |
| `crlf` | CRLF：人读片段折成空格，`--json` 里留成 `\r\n` |
| `collapse` | 同一规则十一处、密度 76.9：组头带密度、只列三处样例、其余八处一句交代；另有两条统计项 |
| `real_doc_agents` | 带统计项：`[统计]` 段 |
| `real_doc_architecture` | 154 处命中、7 组：组序与组内排序 |
| `baseline` | 带基线：开头那行对照、`BaselineHits` 字段 |
